# F1 PITWALL – F1 통합 정보 웹사이트

웹프로그래밍 수업 텀프로젝트 (1인 개발, 조한결). Formula 1 정보를 한 곳에서 통합 제공하는 웹 플랫폼.
GitHub: https://github.com/gksruf22/F1-pitwall

> 이 문서(`PLAN.md`)가 프로젝트의 단일 기준 문서다. 기능이 추가·변경·삭제될 때마다 이 문서를 바로
> 함께 고친다 — 코드와 문서가 어긋난 채로 두지 않는다.

비주얼 디자인(팔레트·타이포·Figma 시안)은 `DESIGN.md` 참고.

## 프로젝트 핵심 원칙

1. **통합 정보 제공**이 큰 틀이다. 기본 정보 · 실시간 · 분석 · AI · 커뮤니티가 **같은 정규화 데이터와
   이벤트 저장소(`ReplayEvent` 테이블)를 공유**한다. 기능마다 데이터를 따로 가져오지 않는다.
2. 화면(클라이언트)은 외부 F1 API를 **직접 호출하지 않는다.** 항상 자체 Express API만 호출한다.
3. 수업 기본 기술은 **HTML / CSS / JavaScript**, 활용 기술은 **DOM / WebAPI / Cloud / Server / AI**다.
   이 기술들을 직접 구현해서 보여주는 것이 목적이므로 **프런트엔드 프레임워크(React, Vue 등)와 CSS·
   차트 프레임워크는 쓰지 않는다.** 차트는 SVG/Canvas로 직접 그린다.
4. 핵심 기능은 실제 데이터로 구현하고, 라이브 기능은 **과거 레이스 시뮬레이션 모드**로 시연한다(이유는
   "실시간 기능 설명" 참고).
5. 백엔드는 **Node.js + Express**를 쓴다 — 프런트·백엔드·수집 스크립트를 JavaScript 하나로 통일해
   수업에서 배운 JS를 그대로 활용한다. (11.15 Spring Boot에서 변경 — Spring 경험이 있다는 이유로 정했던
   것을 "언어 통일·수업 취지" 기준으로 다시 판단함)
6. 계획서에 적은 기능이 기준이다. 기능을 임의로 추가·삭제하지 말고, 바꿀 필요가 있으면 먼저 알려 달라.

## 기능 설명

### 정보 (Info)
F1 시즌·드라이버·팀·서킷의 기본 정보를 제공한다. 시즌 캘린더는 모든 날짜를 **KST**로 보여주고, 그랑프리
결과·순위는 레이스가 끝날 때마다 Jolpica-F1 API에서 갱신한다. 드라이버/팀/서킷 프로필에서 상세 정보와
시즌 성적을 볼 수 있고, 역대 F1 시즌 아카이브(1950~현재)까지 조회 가능하다. 뉴스는 외부 RSS를 매일
가져와 모아서 보여주고, 뉴스·드라이버·팀·서킷·게시글을 한 번에 찾는 통합 검색도 제공한다.
대시보드에는 시즌 진행률·챔피언십 격차·최단 피트스톱 요약 카드와, 결과 데이터에서 규칙으로 뽑은
**기록·하이라이트 피드**(전체/팀/드라이버/루키/레이스/트랙 필터)가 들어가고, 순위표에는 리더와의 포인트
차이와 직전 라운드 대비 순위 변동을 함께 보여준다. 시즌 선택기와 라이트/다크 테마 전환은 모든 페이지
헤더에 공통으로 둔다.

### 실시간 — 라이브 타이밍 & 리플레이
실제 F1 라이브 타이밍 데이터는 상업 라이선스가 필요해 학생 프로젝트에서 직접 구현할 수 없다. 대신
**실제 과거 레이스의 랩 데이터를 그대로 "라이브처럼" SSE로 재생**하는 시뮬레이션 방식을 쓴다 — 이렇게
하면 "실시간 중계" 요구사항과 "과거 레이스 시뮬레이션 모드" 요구사항을 하나의 메커니즘으로 동시에
채울 수 있다. 순위·랩타임·간격·피트스톱·세이프티카 이벤트가 실시간으로 올라오는 것처럼 보여준다.
화면에는 **"Live Timing — Simulated Replay"**라고 정직하게 표시한다. 리플레이 엔진은 같은 데이터를
Canvas 트랙맵 위에서 배속 조절·랩 이동·드라이버 추적과 함께 재생한다(라이브 타이밍과 같은 데이터·같은
순위표 컴포넌트를 재사용).

### 분석 (Analytics)
참고 사이트의 분석 기능을 우리 데이터에 맞게 가져온다. 분석은 두 종류로 나눈다.

- **시즌 단위 (Jolpica 결과로 계산, 항상 제공):** 일관성(레이스·스프린트·예선·스프린트 예선 순위 분포,
  DNF 제외 토글), 드라이버 시즌 스탯(Driver Stats), 헤드투헤드의 레이스·예선 승수, 포인트·포지션 차트.
- **레이스 단위 (사전 수집한 레이스만, 없으면 "데이터 없음"):** 타이어 스틴트, 레이스 페이스(클린랩·
  107% 이상치 제외, 선두 대비 갭, 최속 랩 Top 20), 피트스톱 통계(팀별·드라이버별 평균·최단·표준편차),
  언더컷/오버컷, 헤드투헤드의 예선 랩 격차, Track DNA.

전부 이미 수집된 데이터 위에서 그때그때 계산하며 별도 집계 테이블에 미리 저장하지 않는다. 단 Track
DNA의 서킷 정적 정보(턴 수·랩 길이·고속/저속 코너 수)는 외부 API에 있는지 **확인 게이트**에서 먼저
확인하고, 없으면 수집 레이스 서킷에 한해 직접 정리한 `data/circuits.json`으로 보강한다.

### AI
Claude API를 **서버에서만** 호출해 데이터 기반 질의응답, 자연어 통계 검색(Function Calling/Tool Use로
자체 DB를 조회), 전략 분석, 레이스 요약 리포트, 하이라이트 문장 다듬기를 제공한다. 답변에는 항상
근거 데이터를 함께 보여주고 "AI 생성 내용"임을 표시한다. 호출 횟수·입력 길이를 제한한다.
하이라이트 문장은 서버가 규칙으로 뽑은 사실(수치 포함)을 AI가 자연스러운 문장으로 바꾸기만 하며,
수치를 AI가 새로 만들지 않는다.

### 참여/커뮤니티
Fantasy F1(포디움 예측 → 레이스 종료 후 자동 채점 → 랭킹·예측 정확도), 이벤트 알림(앱 내 알림, 폴링 방식 — 실시간
푸시는 과제 범위 밖), 게시판(텍스트 글/댓글), 즐겨찾기(드라이버·팀)를 제공한다. 전부 하나의 **커뮤니티
페이지** 안에 탭으로 묶는다(개별 페이지로 쪼개지 않는다).

| 8 | AI 어시스턴트 | `/ai` | 대화형 질의응답, 예시 프롬프트, 레이스 요약 리포트 생성 |
| 9 | 커뮤니티 | `/community` | Fantasy 랭킹, 게시판, 즐겨찾기 관리, 알림 센터 |
| 10 | 업데이트 내역 | `/changelog` | 푸터 링크로 여는 정적 페이지 — 날짜별 변경 내역(수작업 목록, 주차 보고서 요약) |

> 이전 초안의 "예측 게임·랭킹"과 "마이페이지"는 별도 페이지로 만들지 않고 **9번 커뮤니티 페이지의
> 탭**으로 통합한다. "관리자" 페이지는 과제 범위를 벗어난다(사용자가 1명뿐인 1인 프로젝트에
> 불필요) — 데이터 수집은 서버 기동 시 배치 작업으로 처리하고 별도 관리 화면은 만들지 않는다.
> → 생략: 관리자 UI, 추후 필요해지면 추가.

## 페이지별 상세 기능

### 1. 통합 대시보드 (`/`)
- **히어로 캐러셀(최상단, 3슬라이드):** ①다음 GP(서킷 사진 + GP 이름 + 카운트다운) ②드라이버 챔피언십
  1위(사진 + 이름 + 포인트) ③컨스트럭터 1위(머신 사진 + 팀 이름 + 포인트). 7초 자동 전환 + 도트
  인디케이터. ②③은 순위 API(`GET /api/standings/drivers`, `/api/standings/constructors`)의 1위 1건만
  쓴다 — `/schedule`의 순위 테이블과 **같은 엔드포인트를 재사용**한다. 배치는 `DESIGN.md` 참고.
- **다음 GP 카운트다운:** (히어로 1번 슬라이드 안) `GET /api/races/next` 1회 호출 후 클라이언트 `setInterval`로 D-day/HH:MM:SS
  틱 — 서버 폴링 없이 로컬 시간 계산만 한다.
- **직전 레이스 포디움:** `GET /api/races/last/podium` → 1~3위 카드(드라이버, 팀, 타임/갭).
- **요약 카드(3개):** 시즌 진행률(`Race` 기준 완료 라운드 / 전체 라운드), 챔피언십 격차(드라이버 순위
  1·2위 포인트 차이 — 순위 API 재사용), 최단 피트스톱(`PitStop` 최소 시간, 카드에 **"수집된 레이스
  기준"** 표기). `GET /api/summary` 한 번으로 내려준다.
- **기록·하이라이트 피드:** 대시보드 하단, 최신순 10개 + 필터 칩(전체/팀/드라이버/루키/레이스/트랙).
  `HighlightService`가 `Result`에서 규칙으로 계산한다(예: 시즌 N번째 우승, 연속 포디움, 폴투윈, 그리드
  대비 최다 상승, 팀 1-2 피니시). AI는 문장만 다듬고 수치는 서버가 계산한 값 그대로 쓴다.
  `GET /api/highlights?filter=`.
- **라이브 상태 배너:** 현재 시뮬레이션 중인 Live Timing 세션이 있으면만 노출(`GET /api/live/status`),
  클릭 시 `/live/{raceId}`로 이동.
- **로그인 시:** 안 읽은 알림 수, 즐겨찾기한 드라이버/팀의 최근 결과 요약.
- 동적 콘텐츠 요건: 카운트다운 실시간 갱신 + 세션 유무에 따른 조건부 배너로 충족.

### 2. 일정·결과·순위 (`/schedule`)
- 시즌(연도) 선택은 **헤더 공통 시즌 선택기**(`localStorage`에 저장)를 쓴다 — 기본값은 현재 시즌, 과거
  연도 선택 시 **시즌 아카이브**(Jolpica가 1950년 이후 전체 지원) 역할도 겸한다. 일정·드라이버·팀 페이지가
  이 값을 공유한다.
- 전체 레이스 캘린더 테이블, 날짜는 **KST**로 변환 표시. 지난 레이스는 결과 링크, 다음 레이스는
  "포디움 예측하기" 버튼(`POST /api/fantasy/predictions`, 레이스당 1인 1회).
- 레이스 상세: 전체 결과표(그리드→피니시, 포인트, 상태/DNF), 패스티스트랩 배지.
- 드라이버·컨스트럭터 시즌 순위 테이블 — 리더 대비 포인트 차이와 직전 라운드 대비 **순위 변동**(▲▼) 열을
  포함한다(`Result`를 라운드별로 누적해 계산).
- 누적 포인트 꺾은선 차트(드라이버/팀별 1개 선) — `Result` 데이터를 그대로 SVG/Canvas로 그린다.

### 3. 드라이버·팀·서킷 (`/drivers`, `/teams`, `/circuits`)
- 목록(카드) → 상세 뷰 구조. 시즌은 헤더 공통 시즌 선택기를 따른다.
- **드라이버 프로필(탭 2개):**
  - *프로필:* 사진/국적/소속팀, 시즌 결과표, 커리어 하이라이트(Jolpica 제공 범위의 우승/폴 수),
    즐겨찾기 토글(`POST`/`DELETE /api/favorites`).
  - *Driver Stats:* 챔피언십 순위·포인트·2위와의 격차, 팀 내 포인트 비중, 팀메이트와 포인트 차이,
    우승·포디움·폴 카드(스프린트 구분), 포인트권 피니시, 전년 대비 포인트 추이, 그리드→결승 비교,
    결승 순위 분포(스프린트 제외), 레이스별 선두 랩 수(수집 레이스만). 대부분 `Result`로 계산한다.
- **팀 프로필:** 현재 드라이버 2명, 시즌 포인트, 컨스트럭터 순위.
- **서킷 프로필(탭 2개):**
  - *정보:* 트랙 맵(좌표 경로를 SVG로 렌더링 — 리플레이와 같은 좌표 데이터 재사용), 랩 레코드, 역대
    레이스 목록.
  - *Track DNA:* 서킷 유사도 버블맵(x=고속 코너 비율, y=저속 코너 비율, 크기=턴 수, 색=타이어
    스트레스) + 턴 수·레이스 거리·랩 길이별 서킷 목록. 수집 레이스 서킷만 표시, 없으면 "데이터 없음".
    코너 데이터가 없으면 **턴 수·거리·랩 길이 목록만** 제공한다(확인 게이트 결과에 따라).
- **드라이버 비교 / 헤드투헤드 (`/drivers/compare?a=&b=`):** 팀 → 드라이버 2명 선택(선택값은 URL 쿼리로만
  관리, 서버 상태 없음), 인기 비교 프리셋(현재 시즌 팀메이트 쌍 + 직접 고른 라이벌 몇 쌍)을 카드로 제공.
  - *항상 제공(Jolpica):* 예선 H2H 승수, 레이스 H2H 승수, 포인트·우승·폴 비교표.
  - *수집 레이스만(OpenF1 예선 랩):* 팀메이트 Q1/Q2/Q3 최고랩 격차 점 차트(양쪽 모두 유효 랩이 있는
    세션만), 팀별 폴 대비 격차 추이.

### 4. 뉴스·통합 검색 (`/news`, `/search`)
- 뉴스 목록: 최신순 페이지네이션, 출처/날짜/외부 링크 표시(`News` 테이블, `NewsFeedJob`이 매일 RSS를
  수집해 채운다).
- 헤더 공통 검색창 → `/search?q=` 페이지에서 `GET /api/search?q=` 결과를 유형별(뉴스/드라이버/팀/
  서킷/게시글)로 그룹핑해 보여준다. 검색은 각 테이블에 대한 `ILIKE` 쿼리 몇 개를 합치는 수준으로
  충분하다(별도 검색엔진 불필요).

### 5. 라이브 타이밍 (`/live/{raceId}`)
- OpenF1로 랩 데이터를 수집해둔 레이스만 선택 가능한 레이스 피커.
- "시뮬레이션 시작" 버튼 → `GET /api/races/{id}/stream`에 `EventSource`로 연결.
- 순위표: 포지션/드라이버/갭/최근 랩타임/현재 타이어 컴파운드가 SSE 이벤트마다 갱신.
- 세이프티카·피트스톱 이벤트는 토스트 배너로 표시.
- AI 질문 박스: 현재 `raceId`를 컨텍스트로 넘겨 AI 어시스턴트 서비스 재사용("지금 1위 누구야?" 등).
- 화면에 **"Live Timing — Simulated Replay"** 문구를 명시(데이터 출처에 대한 정직한 표시).

### 6. 리플레이 (`/replay/{raceId}`)
- `<canvas>` 트랙 맵: 저장된 서킷 경로 위에 `ReplayEvent`의 위치 샘플을 보간해 드라이버별 점을 그린다.
- 재생 컨트롤: 재생/일시정지, 배속(1x/2x/5x/10x — `requestAnimationFrame` 시간 스케일만 바꿈), 랩 점프
  슬라이더(로컬 이벤트 인덱스 탐색, 서버 호출 없음).
- 드라이버 점/행 클릭 시 해당 드라이버 추적(하이라이트 고정).
- 사이드 패널은 라이브 타이밍과 **같은 순위표 컴포넌트**를 재사용하되, 데이터 소스만 SSE 대신 로컬
  타임라인으로 바꾼다.

### 7. 전략·분석 (`/strategy/{raceId}`)
레이스 선택기 + 탭 4개. 앞 3개 탭은 선택한 레이스(수집 레이스만), 마지막 탭은 시즌 단위다.
- **스틴트·전략:** 드라이버별 타이어 컴파운드-랩구간 가로 바(간트 스타일, `PitStop` 경계 기준),
  피트스톱 손익 테이블(전후 포지션/시간 변화), 언더컷/오버컷 하이라이트(피트 전후 구간의 두 드라이버
  `Lap.position` 역전을 서버가 계산, 별도 저장 없음).
- **레이스 페이스:** 랩타임 꺾은선 오버레이(드라이버 선택), **클린랩 토글·이상치 107% 제외 토글**,
  선두 대비 갭 차트(피트스톱 포함 — 같은 랩 기준으로 비교), 포지션 변화 차트, 하이라이트 선택(끔/개인
  최고/최속랩), 최속 랩 Top 20 표. 스피드트랩 Top 15는 OpenF1 응답에 구간 최고속도가 있을 때만 추가.
- **피트스톱 통계:** 요약 카드(최단·팀 평균 최단·가장 일관된 팀(표준편차)·전체 평균·누적 시간), 최단 Top
  20 표, 팀별·드라이버별 평균 바 차트(드라이버/컨스트럭터 토글), 그랑프리별 평균 추이(수집 레이스가
  여럿일 때).
- **일관성(시즌 단위):** 시즌 선택 + DNF 제외 토글, 순위 분포 차트 4종(레이스 결승·스프린트 결승·예선·
  스프린트 예선). `Result`만으로 계산하며 수집 여부와 무관하게 제공한다.

### 8. AI 어시스턴트 (`/ai`)
- 채팅 UI(메시지 히스토리 + 입력창), 메시지마다 `AssistantService` 호출.
- 예시 프롬프트 버튼 몇 개("2023 드라이버 챔피언은?", "이 레이스 요약해줘")로 가능한 질문 범위를
  보여준다.
- 특정 레이스를 골라 "레이스 요약 리포트" 생성 — 해당 레이스의 `Result`/`ReplayEvent`를 근거로 AI가
  요약 카드를 만든다. 화면에 "AI 생성 내용" 문구와 근거 데이터를 함께 표시한다.

### 9. 커뮤니티 (`/community`)
- **게시판:** 목록/글쓰기/댓글(글쓰기는 로그인 필요), 기본 페이지네이션. 이미지 업로드는 범위 밖(텍스트만).
- **Fantasy F1 리더보드:** `FantasyPrediction.score` 기준 랭킹 테이블 + 예측 정확도(적중 횟수 / 제출 횟수).
- **즐겨찾기 관리:** 즐겨찾기한 드라이버/팀 목록, 해제 가능(대시보드 요약과 같은 데이터).
- **알림 센터:** `Notification` 목록, 읽음/안읽음 상태(헤더 알림 종이 여기로 연결).

## 아키텍처

```
Client (Vanilla JS, 멀티페이지 HTML)  ── 대시보드 · 일정 · 드라이버/팀/서킷 · 뉴스/검색
                                         · 라이브 · 리플레이 · 전략분석 · AI · 커뮤니티
        │  REST / SSE (fetch, EventSource)
Express 단일 서버 (Node.js) ── REST 라우터 · SSE(라이브) · 검색 · assistant 서비스(AI)
        │                    · JWT 인증 미들웨어 · ingest(수집/정규화/이벤트화)
        │                    · newsFeedJob · 알림 생성 스케줄 작업
pg (node-postgres, SQL 직접 작성)
        │
Supabase Postgres (DB 전용)      외부: Jolpica-F1(일정/결과/순위) · OpenF1(랩/피트/스틴트,
                                        Node 수집 스크립트로 사전 수집) · Claude Messages API(AI)
```

- 정적 화면도 같은 Express 서버가 `client/`를 `express.static`으로 서빙한다 — 프론트/백엔드를
  별도 호스팅으로 나누지 않는다(SSE가 길게 연결을 유지해야 하므로 서버리스는 피한다).
- 인증은 Firebase Auth가 아니라 **Express + JWT(bcrypt 해시)**로 직접 구현한다 — "Server" 기술을 직접
  구현해 보이는 과제 취지에 더 맞고, 인증 시스템을 하나만 쓰는 게 단순하다. Supabase는 Postgres
  호스팅 용도로만 쓴다. ORM은 쓰지 않고 `pg`로 SQL을 직접 쓴다(집계 쿼리가 많아 오히려 단순).
- 캐시 레이어(Redis 등)는 쓰지 않는다 — 데이터가 미리 수집·저장되어 있어 매 요청마다 외부 API를
  부르지 않으므로 캐시가 굳이 필요 없다.

## 공통 이벤트 모델 (`ReplayEvent` 테이블)

라이브 타이밍·리플레이·전략 분석이 모두 이 형식의 이벤트(행)를 소비한다.

```
ReplayEvent(raceId, seq, ts, lap, type, driver, data jsonb)
// type: GREEN_FLAG | SAFETY_CAR | RED_FLAG | PIT_IN | PIT_OUT | FASTEST_LAP | POSITION_CHANGE
```

- 이벤트는 수집된 원본(`Lap`, `PitStop` 테이블)에서 `ingest`의 정규화 단계가 생성해 저장하고,
  이후 모든 기능이 같은 테이블을 재사용한다(별도 "Event Processor" 모듈로 과하게 쪼개지 않는다).
- 시뮬레이션 모드: 라이브 타이밍 페이지는 SSE 라우트가 `ReplayEvent`를 시간 순서대로 흘려보낸다.
  리플레이 페이지는 전체 배열을 한 번에 받아 클라이언트에서 재생하므로 배속/랩 이동이 서버 호출 없이
  즉시 반영된다.

## 데이터 소스와 제약

- **Jolpica F1** (일정·결과·순위·역대 기록, 1950~현재): 무료, 키 불필요. 익명 기준 호출 제한이 있어
  수집은 `ingest`가 필요한 범위만 가져와 DB에 저장하고, 화면은 항상 DB만 조회한다(매 요청마다
  외부 API를 호출하지 않으므로 제한에 걸릴 일이 거의 없다).
- **OpenF1** (세션·랩·피트·스틴트·순위·위치, **2023년 이후 과거 데이터 무료**): 세션 중 실시간 접근은
  유료라 쓰지 않는다. 호출 제한(초당 3회·분당 30회)이 있어 수집 스크립트에 대기(throttle)·재시도를
  넣고, **레이스 3건 안팎을 미리, 한 번만** 내려받아 JSON으로 저장한 뒤 import 스크립트가 Postgres에
  적재한다. 위치·텔레메트리 응답은 매우 커서 샘플 간격을 줄여 저장한다. 서버 런타임 의존성이 아니라
  사전 준비 스크립트다. Track DNA용 서킷 요약 수치도 이 스크립트가 미리 계산해 함께 저장한다.
  → 수집 대상 레이스는 **2023년 이후**로 한정되고, 엔드포인트·필드는 구현 전 실제 호출로 확인한다.
- **뉴스:** 공개 모터스포츠 RSS 피드를 서버에서 주기적으로 가져온다(스크래핑 아님).
- 엔드포인트·응답 필드는 구현 전 실제 호출로 확인한다(추측해서 작성하지 않는다).
- Render 무료 티어는 유휴 시 서버가 꺼질 수 있지만, 데이터는 Supabase Postgres(영속)에 있으므로
  서버가 다시 켜져도 데이터는 그대로다. 발표 전에는 미리 접속해 서버를 깨워둔다(cold start 확인).

## 기술 스택과 규칙

- **프런트엔드:** HTML5 시맨틱, CSS(변수 · Grid/Flexbox · 반응형, 다크/라이트), JavaScript ES 모듈.
  **멀티페이지 구조**(섹션별 정적 HTML, 일반 링크로 이동) — SPA 라우팅은 쓰지 않는다. 차트는 외부
  라이브러리 없이 SVG/Canvas로 직접 그린다. 서킷 맵은 SVG, 리플레이는 Canvas + `requestAnimationFrame`.
- **WebAPI 활용:** Fetch, EventSource(SSE), Canvas, `localStorage`(간단한 클라이언트 상태 — 예: 드라이버
  비교 선택), `Intl`(KST 변환).
- **서버:** **Node.js + Express(ES 모듈), npm.** 응답은 JSON, 오류는 일관된 형식(`{ error: { code, message } }`,
  Express 오류 처리 미들웨어 한 곳에서 처리).
- **클라우드:** Supabase(Postgres, DB 전용), Render(배포 — GitHub 연동 자동 배포).
- **AI:** Anthropic Claude Messages API를 Node 내장 `fetch`로 **서버에서만** 호출한다(SDK 없이). Tool Use(Function
  Calling)로 자체 API(DB)를 조회해 답하고, 답변에 **근거 데이터를 함께 표시**한다. 화면에 "AI 생성
  내용" 문구를 둔다. 호출 횟수·입력 길이를 제한한다.
- 시간은 UTC로 저장하고 화면에서 KST로 변환한다.

### 코딩 규칙

- 의존성 추가는 먼저 이유를 설명하고 승인을 받는다. 작은 기능은 라이브러리 없이 직접 구현한다.
- 식별자는 영어, 주석과 UI 문구는 한국어.
- 파일 하나는 하나의 책임. 공통 모듈(API 클라이언트, UI 컴포넌트, DB 쿼리 헬퍼, 인증 미들웨어)을
  먼저 만들고 재사용한다.
- 사용자 입력과 외부 데이터를 DOM에 넣을 때는 `textContent` 또는 이스케이프를 사용한다(`innerHTML`에
  그대로 넣지 않는다).
- 비동기 요청에는 로딩 상태와 오류 화면을 항상 둔다.

### 보안

- 비밀 값(DB 접속정보, Claude API 키, JWT 비밀키)은 코드·로그·커밋에 넣지 않는다. `.env`를 쓰고
  `.gitignore`에 올리며, `.env.example`만 커밋한다. SQL은 항상 파라미터 바인딩(`$1`)으로 쓴다.
- 게시판 글/댓글 수정·삭제는 JWT 인증 미들웨어에서 작성자 본인만 가능하도록 권한을 검사한다. 별도
  관리자 권한 체계는 두지 않는다(관리자 페이지가 범위 밖이므로).
- 이미지 업로드 기능은 만들지 않는다(텍스트 게시판만) — 형식/용량 검사 같은 보안 고려를 할 필요
  자체가 없어진다.

### 저작권

- F1 공식 로고·사진·폰트는 사용하지 않는다. 직접 만든 디자인을 쓰고, 화면 하단에 **비공식 팬 프로젝트**
  임을 명시한다.
- 기능 구성은 app.formula1dashboard.com 등을 참고했지만, 화면 디자인·문구·코드는 따라 하지 않는다.

```
server/

                #                  fantasy, posts, favorites, auth ...)
  services/     # ingest, assistant(AI), highlight, newsFeedJob, fantasyScoringJob
  db/           # pg Pool, 쿼리 헬퍼, schema.sql (테이블: race, driver, team, circuit, circuit_metric,
                #  result, lap, pit_stop, replay_event, news, notification, app_user,
                #  fantasy_prediction, post, comment, favorite)
  middleware/   # JWT 인증, 오류 처리
client/         # 정적 프론트엔드 (섹션별 폴더: dashboard/, schedule/, drivers/, news/, live/,
                #                   replay/, strategy/, ai/, community/, changelog/, 공통 css/, js/)

```

## 작업 방식 (Claude에게)

- **기능이 추가·변경·삭제되면 그 즉시 이 문서(`PLAN.md`)의 해당 부분(기능 설명/페이지 구성/
  페이지별 상세 기능/스키마 등)을 같이 고친다.** 디자인(팔레트·타이포·Figma)이 바뀌면 `DESIGN.md`를
  고친다. 코드만 바꾸고 문서를 나중으로 미루지 않는다.
- 한 번에 한 기능만 작업한다. 작업 전에 계획을 3~5줄로 알려 주고, 끝나면 **실행해서 동작을 확인**한
  뒤 결과를 요약한다.
- 불확실한 API 응답·필드는 실제로 호출해 확인한다. 확인하지 않고 지어내지 않는다.
- 주차 말에는 `docs/weekly/YYYY-WW.md`에 한 일·문제·다음 계획을 정리하도록 도와 달라.
- 커밋은 기능 단위로 작고 자주, 메시지는 `feat: …`, `fix: …`, `docs: …` 형식으로 한다.
- 범위가 커 보이면 줄이자고 제안하기 전에, 먼저 **공통 구조로 재사용할 방법**이 있는지 찾는다.
